01 · 项目背景 / 问题分析

传统学习监督的三个核心断点

A

人工观察不可持续

长时间学习场景下，人工监督成本高、主观性强，难以形成稳定数据闭环。

B

云端方案隐私风险高

学习监控涉及摄像头画面，视频流上传会带来明显的隐私和合规压力。

C

规则配置门槛高

用户真正想表达的是自然语言规则，而不是手写复杂 JSON 判定条件。

02 · 核心能力矩阵

从视觉识别到语义反馈的本地闭环

01

实时姿态抽象

YOLO11n-pose 识别低头、侧头、离开、身体静止等关键学习行为。

02

状态稳定判定

后端通过规则引擎过滤抖动，形成专注、分心、离开、低效等稳定状态。

03

本地行为解释

状态变化时调用 Ollama + Qwen，生成简短、可理解的行为反馈。

04

自然语言规则

用户输入口语化要求，系统解析为结构化规则并写入后端规则引擎。

05

学习会话报告

记录专注时长、分心时长、专注率、状态分布，形成学习反馈闭环。

06

前端状态联动

不同学习状态联动卡片、按钮、输入框强调色，降低用户理解成本。

03 · 技术路线 / 系统架构

FastAPI + Vue + WebSocket + Local AI

前端展示层
Vue 3 组件、组合式 API、状态主题变量、学习陪伴对话框。
实时链路层
WebSocket 推送视频帧、检测结果和稳定状态。
服务编排层
FastAPI 路由、摄像头服务、检测服务、状态服务、统计服务。
数据持久层
SQLite 存储学习会话、规则配置和统计结果。
视觉模型
YOLO11n-pose ONNX 模型进行姿态关键点推断。
语义模型
Ollama 本地运行 qwen2.5:1.5b，负责解释和规则解析。
规则引擎
支持自然语言生成规则，也允许高级 JSON 手动配置。
降级机制
本地模型不可用时使用模板文本，保证核心监控链路不中断。

04 · 使用流程 / 产品体验

五步完成本地部署与学习监控

准备模型安装 Ollama，并拉取 qwen2.5:1.5b 轻量模型。
安装环境运行 install-env.ps1 创建或更新 study-monitor Conda 环境。
构建前端运行 build-frontend.ps1 安装依赖并验证 Vue 构建。
启动服务运行 start-all.ps1，同时启动后端 8000 与前端 3000。
开始监控授权摄像头，开启学习 Session，查看解释和统计。
